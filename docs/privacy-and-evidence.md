# Privacy and Evidence Principles

**Current status:** Design requirements, not implemented safeguards.

1. Use synthetic data for development and public demonstrations.
2. Never commit personal exports, account numbers, credentials, session tokens, or private allegations.
3. Preserve original source references and timestamps; derived fields must be labeled.
4. Separate observations, correlations, hypotheses, and confirmed conclusions.
5. Do not automatically merge logical device registrations into physical-device identities.
6. Design explicit user consent, export, and deletion workflows before real-data ingestion.
7. Threat-model local storage, backups, access control, and accidental data disclosure.
8. Review third-party dependencies and security implications before integration.

A compassionate interface should **not** imply that a situation is harmless; a concerning interface should **not** assert compromise without evidence.
